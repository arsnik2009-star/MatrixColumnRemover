# Сравнение методов тестирования ЛР №4

| Метод | Преимущество | Ограничение | Применение в проекте |
|---|---|---|---|
| Анализ причинно-следственных связей | Показывает приоритет правил и ожидаемые эффекты | Таблица растёт при добавлении условий | Основной метод варианта 13. Версия, таймаут, реквизиты и остаток определяют исход перевода |
| Эквивалентное разбиение | Сокращает число однотипных проверок | Ошибка в разбиении может скрыть дефект | Действительные и недействительные имена, суммы, размеры |
| Граничные значения | Находит ошибки диапазона и округления | Сложные связи требуют отдельной таблицы | 0, 0.01, 10.00, 10.01, 80 и 81 символ |
| Покрытие операторов | Находит невыполненные строки | Не показывает непройденный исход решения | Проверить все файлы src через coverage |
| Покрытие решений | Показывает пройденные выходы из ветвлений | Не раскрывает все значения отдельных предикатов | Обе ветви каждой проверяемой развилки |
| Покрытие условий | Позволяет менять каждый предикат отдельно | Нужно учитывать короткое замыкание | Пустая матрица, пустая строка и непустая строка |
| Комбинаторное покрытие | Проверяет взаимодействие условий | Число сочетаний растёт экспоненциально | Все восемь комбинаций наличия трёх обязательных модулей |
| Интеграционное тестирование | Выявляет ошибки на стыках | Сбой бывает сложнее локализовать | FastAPI → процессор → счета, перевод и история |
| Регрессионное тестирование | Фиксирует уже подтверждённое корректное поведение | Требует поддержки набора | Проверки исправлений и отката при отсутствующем получателе |
