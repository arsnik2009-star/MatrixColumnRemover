# Сравнение стратегий интеграции

| Стратегия | Преимущество | Недостаток | Когда применять |
|---|---|---|---|
| Нисходящая | Ранняя проверка внешнего интерфейса | Требуются заглушки | Сервисы с заранее заданным API |
| Восходящая | Ранняя проверка прикладного ядра | Поздно появляется пользовательский интерфейс | Библиотеки и вычислительные системы |
| Сэндвич | Параллельная работа верхнего и нижнего уровней | Сложнее планировать средний слой | Многоуровневые системы |
| Риск-ориентированная | Сначала проверяются наиболее опасные части | Нужна оценка рисков | Проекты с критическими зависимостями |
| Функциональная | Быстро появляется законченная функция | Возможна временная дубликация | Продукты с независимыми сценариями |
| Т-образная | Рано проверяется сквозной путь | Остальные части долго неполны | Большие сервисы с важным основным сценарием |

Для варианта 13 выбрана нисходящая стратегия: REST-контракт и обработка ошибок проверяются раньше внутренних банковских модулей.
