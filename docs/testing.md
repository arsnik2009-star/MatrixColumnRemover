# План и протокол тестирования ЛР №4

Вариант 13, высокий уровень. Сквозной проект — учебная банковская система ЛР №3. Основной метод — анализ причинно-следственных связей, инструмент — pytest. Порог варианта — 75%, порог CI проекта — 90%. В замер включены все модули в `src/`, в том числе консольное приложение из ранних работ.

## План

1. Проверить контракты моделей, классы входных данных и границы.
2. Составить таблицу решений перевода, покрыть ветви и сочетания условий доступности модулей.
3. Проверить взаимодействие REST, оркестратора, счетов, переводов и истории.
4. Воспроизвести дефекты на базе ЛР №3 и повторить проверки после исправлений.
5. Запустить весь набор, coverage и flake8. Повторить проверки в CI на трёх версиях Python.

## Воспроизведение

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -m regression -v
python -m coverage run -m pytest -v
python -m coverage report --fail-under=90
python -m flake8 src tests tools --statistics --count
```

## Причины и следствия для перевода

| Версия | Таймаут | Счета | Сумма | Следствие |
|---|---|---|---|---|
| Не 1.0 | Любой | Любые | Допустимая | VersionConflictError |
| 1.0 | 0 | Любые | Допустимая | IntegrationTimeoutError |
| 1.0 | Положительный | Совпадают | Допустимая | InvalidIntegrationDataError |
| 1.0 | Положительный | Различаются | Больше остатка | InsufficientFundsError |
| 1.0 | Положительный | Различаются | От 0.01 до остатка | Два новых баланса, общая запись истории |

Правила упорядочены по фактическому приоритету. Допустимость суммы по JSON-схеме проверяется до входа в процессор. Ещё 8 тестов перебирают все сочетания наличия трёх компонентов. Допустимо только сочетание, в котором присутствуют все три. Для консольного вывода проверены все достижимые случаи короткого замыкания условия `not matrix or not matrix[0]`.
